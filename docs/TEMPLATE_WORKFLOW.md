# Template-driven job files

Instead of copying individual set snippets into a hand-written GearSwap file, the app can start from a
**blank Mote-Include job file** and fill every set it knows how to optimize. The idea (and the built-in
templates) come from [Masin-M/Gearswap_generator](https://github.com/Masin-M/Gearswap_generator): generate a
complete job file with every `sets.*` block present but empty, then fill it from your gear.

## Workflow

1. Import your gear (GearExport addon JSON or invdump CSV), pick job/subjob, buffs, target, weapon skills,
   Job Points and Master Level.
2. **Optimize all sets.**
3. In the right panel, *Complete job file (template)*: choose a template source and the buff tier to write,
   then **Fill template with optimized sets**.
4. Review the report (which blocks were filled from which result, which were left alone), preview, and
   download `<JOB>.lua`. Drop it in `Windower/addons/GearSwap/data/<Character>/` and `//gs reload`.

## Template sources

| Source | Notes |
|---|---|
| Built-in template | DRG, DRK, NIN, PLD, RDM, RUN, SAM — vendored from Masin-M's `generated_v2/<JOB>_Template.lua` (MIT, see `app/public/templates/LICENSE-Masin-M.txt`). |
| Generic skeleton | Any job. Generated by `template-skeleton.ts`: fast cast, per-job JA blocks, a WS block (+ `.Acc`) for each weapon skill in your list, idle/DT/Town/Kiting, engaged/Acc/DT/Acc.DT, defense sets, THF TH sets, Doom, and the standard Mote hooks. |
| Upload your own | Any Mote-Include style file. Blocks are matched by their `sets.*` path; unknown blocks are copied unchanged. |

## How blocks are matched (`template-fill.ts`)

| Set path pattern | Filled from |
|---|---|
| `sets.engaged`, `sets.melee`, `sets.TP` (+ `.Acc`, mode variants) | TP set |
| `sets.engaged.DT` / `.Hybrid` / `.PDT` (any DT-ish token) | Hybrid DT set |
| `sets.engaged.TH`, `sets.TreasureHunter` | Treasure Hunter set |
| `sets.idle*`, `sets.defense.*`, `sets.Kiting`, `sets.resting` | Idle / DT set |
| `sets.precast.FC*`, `sets.midcast.FastRecast`, Utsusemi, spell-interrupt | Fast Cast set |
| `sets.precast.WS` | first weapon skill in your list |
| `sets.precast.WS['Name']` (+ `.Acc`) | that weapon skill's set — the WS must be in the optimizer table **and** in your WS list |
| `sets.midcast.Cure*` | Healing set |
| nuke / elemental / ninjutsu magic paths | Magic set |
| everything else (`sets.precast.JA[...]`, `sets.buff.*`, pet sets, …) | **left exactly as in the template** and listed in the report |

Slot key style is detected from the template (`ear1/ring1` vs `left_ear/left_ring`). Augmented pieces are
written as `{ name="…", augments={…} }` tables. When the template names a weapon skill you have not
optimized yet, the report offers **Add to weapon skill list** so you can re-run and refill.

`.Acc` variants are currently filled from the same result as the base set (no separate accuracy pass yet);
the report notes this on each such block.
